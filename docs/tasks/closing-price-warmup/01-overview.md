# 장 마감 종가 워밍업 Overview

## 연결 Issue

- Batch Issue: [#1 feat: 장 마감 종가 워밍업 추가](https://github.com/DEPth-FinVibe/Finvibe_Backend_Batch/issues/1)
- Monolith Issue: [#7 fix: 장외 시세와 휴장일 판정 신뢰성 개선](https://github.com/DEPth-FinVibe/Finvibe_Backend_Monolith/issues/7)

## 배경과 문제

장외 종가가 저장소에 없으면 Monolith의 사용자 요청이 KIS 멀티종목 조회를 직접 수행한다. 다수 종목의 첫 조회가 느려지고, 30종목 단위 호출 중 일부가 실패하면 종가 저장소가 불완전하게 채워질 수 있다.

기존 Batch의 장중 가격 업데이트는 Redis의 관심 종목 가격을 갱신하지만 `closing_price` 테이블에 전체 종목의 최근 거래일 종가를 적재하지 않는다. 기존 종가 정리 작업은 장 시작 시 모든 종가를 삭제하므로 재시작·휴장·외부 API 장애 때 활용할 직전 거래일 데이터도 남지 않는다.

## 목표

- 장 마감 뒤 사용자 요청 전에 전체 국내 주식 종가를 적재한다.
- 일부 KIS 배치 실패는 누락 종목만 제한적으로 재시도한다.
- 재시도 후 누락이 남으면 Batch Job을 실패 처리하고 운영 지표로 드러낸다.
- 휴장일에는 불필요한 정규 워밍업을 실행하지 않는다.
- 직전 거래일 종가를 보존하면서 저장량은 최근 30일로 제한한다.
- Monolith의 휴장일 및 최근 완료 거래일 계산과 동일한 규칙을 사용한다.

## 변경 범위

- 평일 15:40 KST 종가 워밍업 Spring Batch Job
- 전체 등록 종목 중 6자리 국내 주식 심볼 대상 선정
- 30종목 단위 KIS 조회와 누락 종목 최대 3회 재시도
- 최근 완료 거래일 기준 멱등 저장
- 지연 기동·수동 복구 application entry point
- 장 시작 전체 삭제 제거 및 30일 보존 정리
- 달력·워밍업·KIS 부분 실패 지표와 테스트

## 제외 범위

- 프론트엔드 변경
- Monolith API 응답 변경
- Kubernetes 및 무중단 배포 설정
- 뉴스·스쿼드 배치 개선
- 장중 WebSocket 프로토콜 변경

## 위험과 제약

- 전체 종목 적재로 장 마감 후 KIS 호출량이 증가한다.
- KIS 응답이 장 마감 직후에도 불완전하면 재시도 후 Job이 실패할 수 있다.
- Monolith와 Batch의 거래일 규칙이 달라지면 잘못된 거래일 키로 저장될 수 있다.
- 기존 Batch 기본 worktree에는 사용자 변경이 있어 별도 worktree에서만 작업해야 한다.

## 완료 기준

- 휴장일이 아닌 평일 15:40에 전체 국내 주식 종가 적재가 실행된다.
- 기존 데이터가 있는 종목은 다시 조회하지 않는다.
- 누락 종목만 최대 3회 재시도하고 최종 누락 시 Job이 실패한다.
- 휴장일 정규 작업은 외부 시세 호출 없이 종료된다.
- 최근 30일 이전 데이터만 삭제한다.
- 스케줄을 설정으로 개별 비활성화할 수 있다.
- 관련 테스트가 통과하고 Monolith PR과 연결된다.
