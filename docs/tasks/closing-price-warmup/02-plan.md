# 장 마감 종가 워밍업 Plan

Overview와 GitHub Issue [#1](https://github.com/DEPth-FinVibe/Finvibe_Backend_Batch/issues/1)을 기준으로 구현한다. 사용자 결정은 연결 Monolith 작업에서 D4~D6을 하나씩 확인해 확정했다.

## 구현 단계

### S1. 거래일 규칙 정렬

- 특정 날짜의 `OPEN/CLOSED/UNKNOWN` 내부 판정 기능을 추가한다.
- 저장 달력 누락 시 KIS 동기화를 시도하고 끝내 확인할 수 없으면 `UNKNOWN`으로 처리한다.
- 15:30 이전에는 전 거래일, 이후에는 당일까지 포함해 최근 완료 거래일을 계산한다.

검증:

- 저장 달력 우선 조회
- 휴장일·달력 장애 분기
- 장 마감 전후 최근 완료 거래일 경계

### S2. 전체 종목 종가 워밍업

- 전체 등록 종목에서 6자리 국내 주식 심볼만 선정한다.
- 최근 완료 거래일에 이미 저장된 종목을 제외한다.
- 남은 심볼을 기존 KIS 멀티종목 경로로 조회한다.
- 누락 종목만 최대 3회 다시 조회한다.
- 동일 응답의 중복 종목을 제거한 뒤 `(stock_id, trading_date)`로 저장한다.
- 최종 누락이 남으면 예외를 발생시켜 Job을 실패 처리한다.

검증:

- 첫 호출 전체 성공
- 일부 성공 후 누락 종목 재시도
- 재시도 소진 시 실패
- 기존 종가 전체 적중 시 외부 호출 없음

### S3. 스케줄 및 복구 경로

- 기본 평일 15:40 KST 스케줄과 ShedLock을 추가한다.
- 휴장일 정규 실행은 외부 호출 없이 건너뛴다.
- 지연 기동·수동 운영을 위한 최근 완료 거래일 복구 entry point를 제공한다.
- cron 프로퍼티를 `-`로 설정해 작업을 비활성화할 수 있게 한다.

### S4. 30일 보존 정책

- 장 시작 시 종가 전체 삭제 Job을 제거한다.
- 매일 16:30 KST에 달력 기준 30일 이전 종가만 삭제한다.
- 정리 스케줄도 별도 cron 프로퍼티로 비활성화할 수 있게 한다.

### S5. 관측성과 검증

- 대상·성공·실패·스킵 종목 수와 마지막 성공 시각을 기록한다.
- KIS 배치 실패와 달력 동기화 실패를 별도 지표로 기록한다.
- 전체 테스트, 컴파일과 `git diff --check`를 수행한다.
- Result 문서를 작성하고 Monolith PR과 연결된 PR을 생성한다.

## 결정 포인트

### D4. 종가 사전 적재 범위와 시각

- A. 전체 등록 종목을 평일 15:40 KST에 적재하고 불완전할 때만 복구한다.
- B. 보유 종목·카테고리 종목만 적재한다.
- C. 별도 워밍업 없이 사용자 요청 시 조회한다.

확정: **A**. 사용자가 보유하지 않은 탐색·모의투자 종목까지 콜드 요청을 제거해야 한다.

### D5. 종가 보존 기간

- A. 달력 기준 최근 30일만 보존한다.
- B. 장 시작 시 전체 삭제한다.
- C. 기간 제한 없이 누적한다.

확정: **A**. 직전 거래일 데이터를 장애 복구에 활용하면서 저장 공간을 제한한다.

### D6. 저장소 전달 방식

- A. Monolith와 Batch에 연결 Issue·브랜치·PR을 각각 만든다.
- B. Monolith만 변경하고 워밍업은 후속 작업으로 미룬다.
- C. Batch만 변경하고 API 계약은 유지한다.

확정: **A**. 조회 계약과 사전 적재가 함께 적용되어야 콜드 패스와 부분 장애 식별 문제를 모두 해결한다.
